🎙️ 本周播客

MAD Podcast — Aaron Levie 谈企业 AI 2026

核心洞察：AI 能力突破的速度快于企业落地的速度，制造了一个悖论——技术越先进，企业部署反而越慢，因为刚落地的东西很快就被新一代能力淘汰。
① Token 成本是头号议题
一个 coding agent 单次任务就能烧掉 $1,000 的计算资源。AI 预算正在从 IT 部门（占营收 3-7%）溢出到业务线预算（占营收 60-80%），市场营销、销售、制造部门需要学会管理自己的 compute budget。
②「无头软件」崛起
软件不再需要 UI，只需要 API 供 agent 调用。这对传统 SaaS 公司的产品形态和商业模式构成根本性挑战。
③ MoE 是主导架构，不是过渡方案
Levie 认为 MoE 是「未来几年甚至更久」的统治性选择。密集模型成本太高，难以支撑大规模 agentic workload。
④ 内部 FDE（非工程师业务专家）出现
企业内部正在涌现一类新角色：能用 Claude Code、Codex、Cursor 快速搭建应用的非工程师业务专家。他们不是开发者，但能用 AI 驱动实际业务流程。
⑤ 创业机会在「桥接层」
将 AI 能力嵌入具体业务流程，做模型商不愿或做不好的集成、变更管理和持续支持。资本市场会自我调节——太封闭的模型商会催生开放生态的反击。

今日思考
Token 成本从 IT 零花钱变成 CFO 议题：SaaS 定价模型的历史转折
Aaron Levie 在播客中指向一个深层变化：AI 预算正在从 IT 部门（占营收 3-7%）溢出到业务线预算（占营收 60-80%）。这意味着市场营销 VP、销售 VP、制造 VP 现在需要学会管理自己的 compute budget——一个他们从未处理过的成本项。$20/人/月的 SaaS 定价模型建立在「软件边际成本趋近于零」的前提上，但 agent 每次运行都在烧真金白银。这不是一个技术问题，这是一个商业模式问题。谁先解决「用量定价 + 业务线可理解」这个方程，谁就能吃掉这波迁移的红利。
变更管理才是真正的瓶颈
Levie 提到一个反直觉现象：AI 能力突破得越快，企业刚铺好的基础设施就越快过时。这制造了一个悖论——技术越先进，企业部署反而越慢。当所有人都在 tokenmaxxing，真正赢的可能是那些把变更管理做对的人。「慢下来」在某个时间点上反而成了竞争优势。
今日一问：你的组织里，AI 的 token 成本目前由谁在管？是 IT 部门默默扛着，还是已经进入了业务线的 P&L？如果明天 CFO 要求每个部门报自己的 AI 预算，你的团队能拿出什么数字？
