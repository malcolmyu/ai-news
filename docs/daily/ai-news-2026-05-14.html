Training Data — Waymo 的二十年征途：从 DARPA 到 2000 万次无人乘车

70|
71| 嘉宾：Dmitri Dolgov，Waymo 联合创始人兼 CTO。这是一场跨越自动驾驶 20 年历史（从 DARPA 挑战赛到今天 2000 万次全无人驾驶旅程）的深度对话。Dolgov 全面拆解了 Waymo 的技术架构、产品化路径和全球化战略。 72|

🧠 Waymo Foundation Model：Driver + Simulator + Critic
83|
Dolgov 明确表示 Waymo 架构是端到端模型，但纯端到端不够。关键在于用"结构化的中间表示"（structured materialized intermediate representations）增强学习到的表征，从而实现运行时验证、闭环训练评估和丰富的强化学习奖励函数。这是一个融合视觉、语言、动作的多模态世界模型。

⚡ "端到端 vs 其他"是虚假二分法
89|
真正的问题不是"端到端还是别的"，而是"端到端 + 还需要什么"。生产级全无人驾驶需要超越基础端到端的能力：运行时验证安全、闭环评估、可调试的中间表示——这些是 demo 或辅助驾驶系统不需要的。

Anthropic Engineering — Claude Code Auto Mode：AI 编程的安全新范式

122|
123| Anthropic 发布了一篇深度技术文章，详解 Claude Code Auto Mode——一种介于手动审批（每次操作都要用户点头）和完全放权（--dangerously-skip-permissions）之间的全新权限模式，试图解决"审批疲劳"这一核心痛点。 124|
125|
126|
127|
128|
🎯 问题背景
129|
Claude Code 默认要求用户审批每个操作，但用户实际接受了 93% 的请求——审批疲劳导致人们忽视真正的危险。而 --dangerously-skip-permissions 又完全没有防护。Auto Mode 是两者之间的中间路线。
130|
131|
132|
133|
134|
🛡️ 两层防御架构
135|
输入层（Prompt Injection Probe）：扫描工具输出内容（文件读取、网页抓取、shell 输出），发现疑似注入攻击时向 Agent 上下文注入警告。输出层（Transcript Classifier）：基于 Sonnet 4.6，在每个动作执行前评估其安全性。采用两阶段分类——第一级快速单 token 过滤（倾向于阻止），被标记的动作才进入第二级链式推理，降低误报。
136|
137|
138|
139|
140|
📊 数据表现
141|
一级过滤：8.5% 误报率（FPR），6.6% 漏报率（FNR）。全流水线（一级+二级）：0.4% FPR，17% FNR。合成数据窃取测试：5.7% FNR。测试集含 10,000 个真实内部调用 + 52 个真实过度积极行为 + 1,000 个合成窃取尝试。
142|
143|
144|
145|
146|
🔒 关键设计决策：分类器看不到助手输出
147|
分类器刻意看不到助手生成的文本和工具结果——这是防止 Agent"说服"分类器放行的关键防御。分类器只读用户消息和工具调用，独立判断。实验证明"Assistant 文本 + 工具结果"的版本表现更差，因为更长的上下文让 Agent 自己的框架影响了判断。
148|
149|
150|
151|
152|
🔄 "拒绝并继续"机制
153|
当分类器阻止一个动作时，Agent 不会停下来等待，而是尝试更安全的替代路径。连续 3 次拒绝或累计 20 次则升级到人工处理。这使得 0.4% 的误报率在用户体验上完全可以接受——一次误报只是让 Agent 换个方式重试，而不是终止会话。

🚗 物理世界的 AI 没有捷径
171|
Waymo 用 20 年证明了一个道理——真正难的问题没有捷径，只有持续的结构性创新和耐心。Dolgov 的"端到端 + 结构化中间表示"方法论对所有在复杂物理世界部署 AI 的团队都有启示：不要被端到端的诱惑简化问题，生产系统需要可验证、可调试的分层架构。
172|
173|
174|
🛡️ 能力越强，安全越要精细
175|
Anthropic 的 Auto Mode 展示了另一个方向：如何在 Agent 能力快速提升的同时，构建与之匹配的安全基础设施。两阶段分类器+防注入探针的组合，以及"拒绝并继续"的失败处理，可能会成为 AI 编程工具的标配设计。0.4% 的误报率配合优雅的重试机制，让安全不再以牺牲用户体验为代价。
