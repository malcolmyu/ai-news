今日要点

OpenAI 于 11 月 5 日发布专用于获授权安全研究的 GPT‑6 Cyber。
官方报告 ExploitGym 成绩为 48.5%，上一代 GPT‑5.6 Cyber 为 32.1%；在其越界诱饵测试中，不带部署提示时有 99.93% 的测试未攻击范围外服务。均为厂商设定的评测，不代表开放环境下的保证；初期访问限定获批的 Daybreak Red 用户。

Thinking Machines 发布 Inkling 2 Small。
官方称该 MoE 模型总参数 5940 亿、激活参数 170 亿，支持图像输入与可变推理强度。目前先在 Tinker 提供闭源使用；完整权重计划在外部安全测试与红队工作完成后于下周以 Apache 2.0 许可发布，尚未兑现。

深度对话

Kevin Roose：资料核查与判断，哪些交给 AI？

Every 于 11 月 4 日发布对科技记者 Kevin Roose 的访谈。以下依据原频道视频与 follow-builders 逐字稿整理；受访者对研究方法和工具效果的描述属于个人经验。
先留下可追溯的资料库
Roose 说写作期间用 NotebookLM 检索大量采访材料、寻找线索与受访者；工具帮助定位证据，书稿仍由他本人撰写。
让多个 Agent 检查草稿
他描述用 Claude Code 中不同视角的 Agent 审看章节、指出事实和叙事问题；这是一种辅助核查流程，并不替代作者对引用的最终复核。
区分“举重”与“叉车”任务
Roose 将通过努力本身获得成长的事比作举重，将只需搬运结果的事比作叉车任务：前者值得亲自做，后者适合借助工具。
公开讨论安全测试
他在访谈中主张模型发布前应有更严格的安全测试。这是受访者的政策观点，而非现行通用规则。

今日思考
GPT‑6 Cyber 的发布把“能发现问题”与“能否守住授权范围”并列评估；Inkling 2 Small 则把开放权重安排在外部测试之后。企业案例展示了更快的开发节奏，而 Kevin Roose 的访谈和 Ryo Lu 的发言提醒，哪些判断必须由人形成，仍要在任务开始前说清。
今日一问：你的 Agent 知道哪些系统可以碰、哪些动作必须停下来请人决定吗？
今天可做：挑一条真实工作流，分别列出允许访问的资源、必须人工批准的动作，以及交付时能复核的证据；再用越界情形试跑一次。
