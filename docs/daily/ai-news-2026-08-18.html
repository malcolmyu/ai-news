Thibault Sottiaux @thsottiaux
Here is how to enable a 1M-token context window in Codex for GPT-5.6 Sol. Even though we have tuned the context limit in Codex to be set optimally when it comes to performance and cost, this is a common ask, so here it is documented. A larger context window lets Codex retain more code, tool output, and conversation history before summarizing older material. You need a model that supports it. And GPT-5.6 Sol, for example, has a documented 1,050,000-token window. Open ~/.codex/config.toml and add or update these settings at the top level, before any [section] headers: model = "gpt-5.6-sol" / model_context_window = 1000000 / model_auto_compact_token_limit = 900000. The first setting selects the model. The second tells Codex to use a one-million-token context budget. The third starts automatic history compaction around 900,000 tokens, leaving some headroom. Restart Codex client and start a new session after saving. Have fun, but also know that we tuned the default carefully!
如何在 Codex 中为 GPT-5.6 Sol 开启 100 万 token 的上下文窗口。虽然 Codex 的上下文限制是经过性能与成本调优后设定的，但这是常见需求，所以记录下来。更大的上下文窗口让 Codex 在压缩旧内容之前保留更多代码、工具输出和对话历史。你需要一个支持它的模型——例如 GPT-5.6 Sol 官方文档记载有 105 万 token 的窗口。打开 ~/.codex/config.toml，在顶层（任何 [section] 之前）添加或更新：model = "gpt-5.6-sol"、model_context_window = 1000000、model_auto_compact_token_limit = 900000。第一条选择模型，第二条指定 100 万 token 的上下文预算，第三条在约 90 万 token 时自动开始压缩历史，留出余量。保存后重启 Codex 客户端并开新会话。玩得开心，但也要知道我们精心调优过默认值！
