01 · 范式畅想

未来开发：自然语言总指挥，Agent 蜂群执行

工作假设（非终局定论）：最佳软件工程体验不是「人写更多代码」，而是人握意图、规格与验收权，由 Personal Agent（Orchestrator）把任务拆给多个 Code / GUI Agent（Executor），在 Harness 约束下闭环执行。
发版前 walkthrough：你对 Orchestrator 说「今晚发版」。它派出三个子 Agent：一个改仓库并跑结构校验；一个用自动化测试 + 全链路日志断言业务路径；一个对关键屏做截图 diff。你只在汇总面板前签残留风险——不再逐行读 diff，除非某轨失败并附带证据链。
五条原则：（1）契约进仓库，不进聊天；（2）验证分层，硬锚优先；（3）失败可恢复、轨迹可回放；（4）模型变强 Harness 变薄，但不消失；（5）人永远握最终 merge 权。

02 · 已跑通样本

第二号：Orchestrator + Executor + 仓库契约

「第二号」不是普通静态站，而是内容生产 Harness 的试点：几乎全程用自然语言驱动 Hermes 调度、Codex 在仓库内执行。复杂度的核心不在 GitHub Pages，而在稳定、可复查、可验证地生产日报与调研报告。
H
Hermes — 调度与发号施令
选择 docs/agents/skills/ 内项目 skill，拼装任务，不直接写文件。
C
Codex — 仓库内执行
改 HTML/CSS、跑 site:validate、浏览器验收、重建 Pagefind 索引。
R
仓库 — 权威契约
docs/agents/contracts/、scripts/site_harness.py、.github/style-check.sh。全局 skill 只能引用，不能覆盖。
02 · 验证闭环

一条标准流水线

  1. Hermes 选 skill → Codex 生成页面与资源
  2. npm run site:update 刷新首页与归档
  3. npm run site:validate + style-check.sh
  4. 内容变更时 npm run build:search
  5. 布局/媒体变更时浏览器检查桌面 + 390px 移动端
检查层机制类比移动「双轨」
结构 / 逻辑轨雏形site_harness.py validate日志 + 自动化断言
视觉 / UI 轨雏形浏览器 390px 验收截图 diff、布局回归
一条教训：validate 通过 ≠ 瀑布流对齐、搜索弹窗、架构图嵌入一定正确。结构可机验 ≠ 像素与交互可机验——这正是移动端要补的课。
03 · 差距（全文脊梁）

常规工程（尤其移动端）与第二号差在哪？

第二号证明：在验收边界清晰的任务上，自然语言 + Agent 蜂群已能稳定交付。移动端缺的不是 Copilot 式补全，而是轨迹级、双轨、可并行的验收基础设施。
维度第二号（内容 Web）常规移动 App
任务难度约 L1～L2普遍 L3～L4（跨屏、跨 App）
硬锚HTML schema、链接、token权限弹窗、系统 UI、网络时序
执行面文件系统 + 浏览器模拟器 / 真机 / 系统服务
失败证据validate 日志 + 截图需全链路 trace（console / network / DOM）
参考 MobileGym 分级：L4 跨 App 工作流上最强模型成功率仍约 22%——瓶颈在可验证性与执行面，不在「会不会点屏幕」。

04 · 弥补路径

双轨验收 + 近真执行集群

逻辑还原
自动化测试 + 全链路日志（console、network、Element 等）+ GUI Agent 操作 + 截屏留证。回答「对不对、完没完、卡在哪一步」。
UI 还原
相对设计稿或 baseline 的视觉/布局 judge。回答「像不像、偏在哪」。与逻辑轨并行，谁先跑视任务而定；失败必须分因。
执行面（L1 架构，不含运营细节）：
与模拟器的分工：Sandbox 侧重规模（nightly、并行、确定性 judge）；真机集群侧重终验（系统权限、厂商 ROM、网络时序）。多 Agent 集群是放大器，不替代双轨 judge。
05 · 双向追赶

从起点与终态往中间收敛

从起点追（第二号 → 移动）
把「契约进仓库 + 命令门禁」迁移为移动任务模板：规格 YAML、judge 脚本、trace 存储路径。先 L2 单 App 多步，再碰 L4。
从终态追（蜂群 → 今日）
先在一个仓库插双轨 judge，再扩 Agent 池与真机槽位。规格锚定（如 OpenSpec）防长程目标漂移——见 OpenSpec 调研。
05 · 模型 vs 编排

Harness 会变薄，不会消失

模型越强，Harness 越薄，但不会消失。约束从 Prompt 沉入代码与 judge；审查从人眼沉入双轨自动化。详见 多 Agent 调研 中的 Big Model / Big Orchestration 讨论。
06 · 近期试点

三条可执行验证（团队对齐用）

① 逻辑轨
选一个 L2 移动任务（单 App、多步）→ 产出「Agent 轨迹 + console/network 断言」模板。Done：nightly 无人值守红/绿，失败可定位到步骤。
② UI 轨
同任务或同屏建立 screenshot baseline + diff 门禁（与逻辑轨并行，顺序任选）。Done：行为失败与视觉失败可分因。
③ 执行面
Sandbox 批量 + 真机抽验一条 Sim-to-Real 闭环。Done：至少 1 个任务可度量 sim/真机结论一致率。
