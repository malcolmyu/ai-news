为什么需要多智能体系统？

一个 Agent 的上下文窗口有限、一次只能聚焦一个任务、出错时没有监控和回收机制。多智能体架构的本质是 分工 + 约束 + 反馈：把大问题拆成小任务，每个子 Agent 只有少量工具，用代码而不是 Prompt 做验收。结果是更可靠、可追踪、可迭代的工作流。
「只会写代码的程序员一定会被取代，但会设计 Harness 的工程师会迎来自己的黄金时代。」

02 · Architecture Patterns

四大架构编排模式

🧠 中央协调 (Orchestrator)

主 Agent 不写代码，只分解任务、分配子 Agent、聚合结果。Hermes 的多 Agent 编队、OpenAI Codex CLI 的 Plan → Code → Review 均属此模式。子 Agent 返回文件路径和状态码。

📡 事件驱动 (Event-Driven)

Agent 通过消息队列通信。一个 Agent 的输出触发下一个 Agent 的输入。适合流式处理 pipeline（如 RSS 采集 → 摘要 → 发布）。LangChain 的 graph 运行时是其代表。

🔄 循环迭代 (While Loop)

Rust/Python while 循环启动新 CLI 会话，文件系统传递上下文。代表：Ralph。局限：自己开发自己测试时效果一般，缺少独立视角。

🏛️ 专家编队 (Swarm)

每个 Agent 是领域专家，路由层根据任务类型派发。Stripe 的每个 Agent 只看筛选子集工具。Vercel 将工具从 15 个减到 2 个，准确率从 80% → 100%。

04 · Implementation

多 Agent 编队的实现关键

🧩 主 Agent 不写代码

协调层只负责：分解任务 → 分发 → 聚合结果。不参与开发、不碰文件。始终从状态码和摘要理解进度，按里程碑输出确认。

📁 文件系统即通信

子 Agent 输出到文件，主 Agent 读取文件。不需要 RPC、消息队列。文件路径 + 状态码 = 足够的生产级通信协议。

✂️ 工具越少越好

每个子 Agent 只看筛选子集工具。Vercel 实验：15→2 个工具，准确率从 80% 跳到 100%。约束比指令有效。

🔄 错误剥离原则

写 Bug 的 Agent 修 Bug，提 Bug 的 Agent 验收。不交叉、不混淆。修正循环最多 3 次，超出则留人工介入。
05 · Framework Comparison

主流多 Agent 框架对比

Hermes Agent

基于 delegate_task 的原生多 Agent 支持。支持并行子 Agent（最多 3 并发）、隔离上下文、Acp 协议集成。

亮点：单个会话内自动拆解、多 Agent 并行、结果聚合。

Ralph

Rust while 循环驱动 Claude CLI，文件系统传递上下文。轻量但缺乏隔离。

亮点：完全无服务器依赖，纯 CLI 生态。

OpenAI Codex CLI

Plan → Code → Review 三段式。每个阶段一个 Agent 做一件事。但 review 阶段不是独立第三方。

亮点：官方维护，与 GPT 生态深度整合。

Claude Code (CC)

Anthropic 的官方 CLI Agent。非原生多 Agent，但可通过脚本编排多个实例。

亮点：Claude 模型直接驱动，质量上限高。

Practice

实操建议

  • 起步从 主 + 1 个子 Agent 开始
  • 每个子 Agent 只配 2–3 个必要工具
  • 用 AGENTS.md + file 协议 代替复杂通信
  • 先跑通 Happy Path，再补错误处理
  • 审查 Agent 必须是 独立上下文
  • 失败超过 3 次 → 人工介入不丢人

07 · Debate

Big Model vs Big Orchestration

更强的模型是否意味着多 Agent 不再必要？行业顶级实践者给出了截然不同的答案。
Big Model
Noam Brown
OpenAI
"Harness 是拐杖，推理模型一来很多基础设施就不需要了。" 一个模型搞定一切，多 Agent 是过渡方案。
Big Orchestration
Jerry Liu
LlamaIndex
"模型是引擎，Harness 是方向盘和刹车。" 多 Agent 不是能力问题，而是工程可靠性问题。
两者都在理。 模型越强，Harness 越薄，但不会消失。架构约束、反馈循环、熵管理只会换形态——从 Prompt 约束变成代码约束、从手动审查变成自动验收。就像自动驾驶：L2 需要人盯，L4 不需要盯但需要冗余传感器和 Failover 机制。
08 · Ecosystem

开源生态与关键工具

🔧 LangGraph

基于图的多 Agent 编排。支持条件分支、循环、人机交互。适用：复杂工作流。

🔧 CrewAI

角色驱动的多 Agent 框架。定义 Agent Role / Goal / Backstory，自由组合。适用：快速原型。

🔧 AutoGen

微软开源，多 Agent 对话框架。支持群聊、子 Agent、代码执行。适用：研究实验。

🔧 ACP 协议

Agent Communication Protocol。标准化 Agent 间通信，Hermes / Copilot 可互操作。
Conclusion
多 Agent 的真正价值不是"多个模型一起工作"，而是"让每个模型在自己的约束范围内可靠工作"。
判断多 Agent 系统成熟度的三个问题：
  1. 一个子 Agent 出错时，整个系统怎么恢复？
  2. 上下文怎么在 Agent 之间传递而不膨胀？
  3. 最终代码质量由谁来把关——模型自己还是独立的审查 Agent？
工程师的价值转变：从写代码 → 设计让 Agent 可靠工作的系统。多 Agent 编队的时代，最稀缺的不是会写代码的人，是会设计 Harness 的人。
