01 · 问题背景

被忽视的中间层：Harness 才是 Agent 表现的关键

过去 Agent 开发者几乎把全部注意力放在基座大模型上，认为模型越强，Agent 越强。但近期研究发现，真正决定 Agent 表现的往往是中间那层运行时 Harness——它负责把模型、提示词、工具、记忆和控制流串起来，决定任务如何拆解、工具如何调用、决策如何流转。
当前主流 Agent 框架（LangChain、AutoGen、Claude Code、DeerFlow）的 Harness 全部靠人工静态开发。换模型、换工具、换领域就要重写脚手架。更严重的是提示词、工具封装、重试、记忆全搅在同一条代码里，改一处牵一发动全身，跨场景复用只能靠复制粘贴。
02 · 核心洞察

双重天花板：模型与 Harness 优化互不连通

更大的问题是，Harness 产出的运行轨迹数据被白白浪费，模型提升也无法同步更新调度策略——两者优化互不连通，形成双重性能天花板。小米 Darwin Agent Team 的目标就是打破这个天花板：让 Harness 从「手工一次性搭建」变成「可组合、可观测、可演化的工程系统」。
"把 AI Agent 的运行时框架变成可序列化、可哈希、可直接替换的一等公民。"— HarnessX 论文

03 · 架构设计

HarnessX 三大创新组件

1. 可组合 Harness：像搭乐高一样插拔

研究团队把 Harness 提升为一等公民——能序列化、能哈希、能直接替换。最小积木块是 Processor，通过八个生命周期钩子把控制点精确卡死，配合九维行为分类覆盖模型选择、上下文管理、记忆系统、工具调用、沙箱环境、奖励信号、安全边界、追踪日志到训练桥接的全链路。想加功能、换逻辑、删组件？就像搭乐高一样直接安全插拔——冲突自动拦住，其他代码一行都不用动。
8 个生命周期钩子：on_start → on_tool_select → on_tool_execute → on_observe → on_reason → on_act → on_error → on_stop
9 维行为分类：模型选择、上下文工程、记忆管理、工具封装、沙箱编排、奖励设计、安全策略、可观测追踪、训练桥接

2. AEGIS 进化引擎：让 Harness 自己看轨迹、学教训、越跑越聪明

AEGIS（Adaptive Evolutionary Generation & Improvement System）把 Harness 演化直接映射成强化学习 MDP：
状态 = 当前 Harness 配置 + 历史轨迹库
动作 = 安全编辑（加工具、改提示词、重构控制流）
奖励 = 任务得分 + 完整轨迹质量
四阶段流水线全由同一个元大模型驱动：
① 压缩 — 将海量原始轨迹压缩为关键故障摘要，过滤噪声
② 规划 — 识别哪些坑踩过、哪些方向还没探索
③ 生成 — 产出类型安全的候选 Harness 修改方案
④ Critic 审核 — 盯着奖励欺骗（reward hacking），确定性闸门强制要求「新方案不能让任何已解决任务变差」，彻底解决灾难性遗忘

3. 协同进化闭环：模型和 Harness 一起越变越强

Harness 演化和模型 RL 训练共享同一个回放缓冲区：Harness 端用 AEGIS 做无参数符号化编辑（修改的是脚手架，不动模型权重），模型端用跨 Harness 的 GRPO 做参数微调。同一个任务在不同 Harness 下跑出的轨迹放在一组比较相对优势，模型就能学会在各种执行流程中都能找到最优策略，而不是死磕单一固定套路。
关键优势：离线复用轨迹，几乎零额外环境交互成本。Harness 和模型可以在同一个闭环中共同提升，突破各自独立优化的天花板。

06 · 当前局限

三个待解决的短板

⚠️ 域外泛化未验证

进化过程仅在同分布任务上测试，跨域迁移能力未知

⚠️ 文本动作空间限制

面向离散文本动作的 Agent，连续控制或多模态场景是空白

⚠️ 强元模型依赖

AEGIS 高度依赖 Claude Opus 4.6 级别的元模型驱动进化，成本约束明显
07 · 意义与展望

HarnessX 对 Agent 研发范式的影响

HarnessX 的贡献不只是性能数字。它首次系统性地证明了Agent 运行时层可以像模型权重一样被精确定义、序列化和自动优化。
对实际工程的意义：
① 不再需要人工反复调 Harness — AEGIS 自动从轨迹中学习，专注力放在任务定义上
② 弱模型 + 好 Harness 可能胜过强模型 + 烂 Harness — Qwen ALFWorld 53%→97% 就是证明
③ 跨场景复用不再是复制粘贴 — Processor 原子化后，跨项目插拔像搭乐高
④ Harness 层优化是新的工程杠杆 — 比换更大的模型更具成本效益
随着后续跨域泛化、多模态动作空间和弱元模型方案的探索，这条路径有机会真正把 Agent 运行时层从「手工搭建」推向「持续自我进化」。
