What Broke & What Replaced It

Agentic Coding 成为组织默认后——4 条被重写的团队规范

📋 Planning → JIT Planning
6 个月 roadmap 第三个月就作废了——因为 Claude Code 本身加速了研发。JIT Planning（像 JIT 编译器，在正确时间做刚好够的规划）。设计文档被 PR + Prototype 取代。「先做原型，让内部用户用起来，根据反馈迭代。」
👤 Code Ownership → Ask Claude
「谁写的这段代码？」在每行都有 Claude 辅助的时代已无意义。新规范：双击问题——你到底想知道什么？谁导致的回归？谁能回答客户问题？然后先问 Claude。同时问自己：「这个问题能自动化吗？」
🔍 Code Review → Trust but Verify
Claude 管：风格、lint、bug 检测、自动加测试、PR 反馈
人类管：法律审查、信任边界、安全敏感代码、产品品味
关键警告：平衡点会随模型进步不断变化，需要持续评估。
🔀 Team Makeup → Roles Blur
PM 开始写原型代码。工程师接手内容设计和 UX。招募重点：有产品感的创意构建者 + 深度系统专家。不再看重原始编码吞吐——模型替你解决速度问题。
Technical Debates

「When building is cheap, arguing is expensive.」

Fiona 刚加入时和 Boris 有一次技术辩论。她差点用老办法——「走，去白板前讨论」。然后她刹住了：用 Claude 生成了 3 个不同实现的 PR。

⚠️ 警告：不要让「最后提交的人赢」。Fiona 强调需要强烈的团队文化和对齐机制——不能有人半夜 3 点提交 PR 抢最后话语权。
Verification

「Shift Left」——验证前置

吞吐量暴增 →「有新的方式可以搞砸」。Fiona 分享了一个亲身经历：修了个 bug，第二天在 Boris 的 X 线程里看到有人 @ 他说发现了新 bug——那种「是不是我干的」的沉没感。
解决方案：Shift Left——自动化验证尽量往前移，在用户发现之前拦截。而且角色模糊化后，设计师和 PM 也在提交代码，需要让每个人都对自己改动的安全性有信心。

Org Structure

「招募官以为我疯了」

Fiona 加入后要求：所有管理者先从 IC 做起。招募官说：「没有经理会对这个感兴趣。」她回答：「这就是 Claude Code 团队的 dogfooding 文化。不感兴趣的，早点分开更好。」
之前 Meta 时代每年勉强交一个 PR——内部工具和工作流总在变，学会一个命令就过时了。现在git 命令都不记得了，全部让 Claude 做。
组织保持尽可能扁平。Claude Code + Cowork 共享一个团队使命，pod 之间人员自由流动。
Governance

二层治理：刚性原则 + 团队自治

🔵 Must-Do（刚性规则）
• 每个团队成员（含跨职能伙伴）必须使用 Claude Code + Cowork
• 「Claudify 一切你能 Claudify 的」——总是问：Claude 能不能替我做这个？
• 明确授权杀死旧流程——每几个月复审：这条规则还在服务最初的目的吗？
🟢 Room to Adapt（pod 自治）
• 每个 pod 自己决定 Claude 如何在 triage/standup/on-call 中发挥作用
• 哪些工作流优先「Claudify」
• 不强制「你必须自动化这个」——只给建议，让团队根据自己面对的问题做选择

Actionable Playbook

如果你也想启动组织转型

1
三个指标打基线
Onboarding 时间、PR cycle time、AI-assisted commit 比例。别只看吞吐量——真正的指标是你想解决的问题是否被更快解决了。
2
主动杀死流程
流程不会自己消失。给团队明确授权去质疑和终止过时流程。定期复审：这条规则还在服务最初的目的吗？
3
JIT Planning
像 JIT 编译器一样规划——在正确时机做刚好够的规划。6 个月 roadmap 已死。原型 + 内部用户 + 快速迭代。
4
代码即真相来源
停止维护独立 wiki。Fiona 回答客户问题的方式：打开 Claude Code 加载本地 repo，直接问代码库。如果还有好 spec，check in 到 repo 里让 Claude 对照验证。
5
二层治理
刚性原则（dogfood、Claudify、杀流程）强制统一。执行层面放权给 pod——每个团队自己决定哪些流程先被 AI 化。
