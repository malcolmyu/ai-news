What Broke

当 Agentic Coding 成为组织默认 — 5 个被打破的流程

📋 Planning Norms
6 个月 roadmap 在 3 个月后作废。从预计算式规划转向 JIT Planning（像编译器，不是瀑布）。设计文档被 PR + Prototype 取代。
👤 Code Ownership
「谁写的这段代码？」在每行都有 Claude 辅助的时代变得诡异。新解法：重新定义问题——到底想知道什么？谁导致的 regression？谁能回答客户问题？
🔍 Code Review
新的规模需要新工具。Claude Code Review 处理风格、lint、bug 检测、自动加测试。人类留给自己：法律审查、安全边界、产品品味。
🔀 Team Make-up
角色边界模糊——工程师做内容设计、PM 写代码、非技术人员用 AI 构建。Fiona 在招聘上更看重 创意构建者 和 系统专家，降低对原始编码吞吐的权重。
📚 Knowledge Sharing
文档不再是真理来源——代码库本身成了真理来源。Fiona 说她在 Claude Code 团队连续 4 个月没见过一个非 Claude 辅助的 commit。
⚡ Security
更多代码 = 更大的攻击面。安全审查需要跟上 AI 的产出速度。Cross-functional 伙伴（法务、设计、合规）也需要跟上节奏。
转型模型

二层治理：Forcing Functions + Room to Adapt

🔵 Forcing Functions（刚性规则）
• 每个工程师必须使用 Claude Code
• 「把所有能 Claudify 的都 Claudify」
• 明确授权杀死旧流程
🟢 Room to Adapt（团队自治）
• 每个团队自己决定 Claude 如何在 triage/standup/on-call 中发挥作用
• 哪些工作流优先「Claudify」
• 原则统一，执行放权
"Mandate the principles. Let teams own the implementation."
Leaders Should Baseline

每个工程 Leader 必须追踪的 3 个指标

🆕 Onboarding 加速
新工程师/设计师/PM 的上手速度
指标
🔄 PR Cycle Time
从写代码到合并的时间。如果没缩短，瓶颈在 CI/CD
指标
🤖 Claude-assisted Commits
指标
在 Claude Code 团队：100% 的 commit 都有 Claude 辅助。连续 4 个月未见非 Claude commit。
Code Review 新范式

AI 处理批量 · 人类保留判断

AI 管：风格、lint、bug 检测、自动加测试
人类管：法律审查、信任边界、安全敏感代码、产品品味
"Trust, but verify."
— 在全面自动化审查和保留人类判断之间的平衡，Fiona 坦承这仍是开放问题
招聘转型

不再看原始编码吞吐

Fiona 的招聘新标准：
🔥 创意构建者
好奇心 · 迭代能力 · 产品品味
⚙️ 深度系统专家
分布式系统 · 基础设施 · 安全
降低对原始编码吞吐的权重 —— 因为编码不再是稀缺能力。
Fiona 尚未解决的问题

AI-Native 组织的开放问题

📱 平台团队拆分还有意义吗？
iOS 和 Android 分开两组，在 AI 跨平台能力提升后还合理吗？
🎯 角色边界模糊下的生产力
当角色多元化，如何确保每个人都同样感受到生产力提升？
Actionable Playbook

组织的可操作建议

1
基准三个指标
Onboarding 时间、PR cycle time、AI 辅助 commit 比例。如果 PR cycle 没缩短，说明瓶颈在 CI/CD 而非 AI 采纳。
2
主动杀死流程
找出团队最头痛的工作流。问：它还在服务它的目的吗？然后要么自动化它 —— 要么杀了它。
3
JIT Planning
像编译器那样规划 —— 在正确的时机做正确量的规划，不多不少。6 个月 roadmap 已死。
4
代码库即真理
停止维护 wikis。Fiona 回答客户问题的方式：打开 Claude Code 加载本地代码库，而非翻 Confluence。
"Pick your noisiest workflow. Your most expensive one. The one your team dreads. Ask: Is it still serving its purpose? Then either automate it — or kill it."
— Fiona Fung

3

Why This Matters

为什么值得你关注

你自己就在跑类似的转型。你用 Hermes + Claude Code 多 Agent 编队、Ralph Loop、cron 调度 —— 这已经是 AI-native 组织的雏形。
Fiona 的反思直接映射到你遇到的问题：
• 「Claude Code build passed ≠ runtime 正常」→ 验证是瓶颈
• 多 Agent 协调中「主 Agent 只协调不写代码」→ Ownership 重构
• 「写 bug 的人修 bug、提 bug 的人验收」→ 责任制闭环
Key Takeaway

「过去为你服务的东西，可能不再为你服务。」

Fiona Fung 的演讲传递了一个清醒的信号：工具采纳不是终点，而是组织变革的起点。

当编码不再是瓶颈，真正的限制变成了你如何组织人、如何做决策、如何定义卓越。
AI-native 组织的核心竞争力不是用 AI 写更多代码，而是重新设计那些围绕「写代码慢」建立起来的流程。
