01 · 核心判断

真正的新意不是「记忆」，而是「行为模式自动提炼」

这套系统把 Agent 记忆拆成两类：Instinct 记行为模式，例如你总是先读规范再改代码；Memory 记知识事实，例如项目决策、用户偏好、已知 bug。前者影响行动策略，后者减少冷启动成本。
关键分界：向量检索记忆已经是成熟范式，Hermes、Mem0、Zep 等路径都有替代实现；但基于 Claude Code Hook 的确定性行为观测，能把「你怎么工作」从聊天噪声里提炼出来，这是更难迁移、也更有护城河的部分。
可信度

先降温

数据未独立验证

10 分钟到 30 秒、Token 降 78%、重复错误降 80% 都缺少测量口径。

02 · 三层架构

从工具调用，到本能规则，再到会话启动记忆

1
行为观测层：Hook 捕获事实流
PreToolUse / PostToolUse 捕获每次工具调用并写入 JSONL；Stop Hook 在会话结束时触发分析。超过 5MB 或 8000 行按月归档，主文件只保留 30 天，避免观测日志无限膨胀。
2
模式提炼层：规则检测 + Haiku 语义分析
会话结束后走双路径：硬编码统计检测覆盖 5 种预定义模式，Claude Haiku 补足语义理解。输出的 Instinct 是独立 Markdown 文件，包含 trigger、action、confidence。
3
记忆注入层：本地 Embedding + Qdrant 召回
6 类记忆（feedback、project、user、decision、bug、knowledge）用本地 nomic-embed-text 向量化，Qdrant 做余弦相似度检索。SessionStart 用项目名和最近 3 条 git commit 构造查询，召回 Top-5 注入系统提示。
03 · Instinct 机制

一条规则只做一件事，才有演化空间

得物方案把 Instinct 设计为原子单元：一个 trigger 对应一个 action，再加 confidence。首次出现设为 0.5，重复触发每次 +0.05，上限 0.9；长期不触发 -0.05，低于 0.55 标记 deprecated。
机制作用评价
原子性一条规则只描述一个触发和动作利于合并、衰减和审计
置信度演化重复增强，沉默衰减比静态 memory 更接近行为学习
Jaccard + Union-Find合并重复或相近规则可解释、低成本，但阈值经验化
domain 聚合同域规则超过 2 条生成 evolved-{domain}.md能形成更高层的行为摘要
04 · 防膨胀

记忆系统的难点是忘掉，而不是记住

日志层裁剪
观测流按大小、行数和时间归档，避免 JSONL 成为永久垃圾场。
规则层遗忘
Instinct 置信度随触发频率变化，长期无用的规则自然退场。
注入层限流
SessionStart 只召回 Top-5，而不是把所有 memory 一次性塞进上下文。
聚合层覆盖重写
rules/auto-evolved.md 每次会话覆盖重写，避免演化产物线性堆积。

06 · 好的部分

这套设计抓住了 Agent 记忆的关键矛盾

Hook 优先是正确架构

确定性触发比模型主动记得调用某个 skill 更可靠。

双路径分析务实

统计规则便宜稳定，语义分析覆盖隐性模式。

Jaccard 去重可解释

在短规则文本上，比 Embedding 相似度更容易审计。

隐私边界清晰

Embedding 本地化，避免把个人工作记忆发往云端。
07 · 潜在问题

把个人习惯学进去，也会把噪声学进去

单用户过拟合
系统越贴合一个人的局部习惯，越可能强化临时 workaround 或坏味道。
Stop Hook 阻塞风险
会话结束时做分析很自然，但若分析链路慢或失败，会影响退出体验和数据一致性。
阈值工程缺少基准
Jaccard 0.5、置信度 0.55、同域 2 条聚合都需要真实项目数据校准。
Qdrant 对个人系统偏重
若只有单机、单用户、小规模记忆，SQLite + 向量扩展或轻量索引可能更低运维。
08 · 对 Hermes 的启示

Hermes 缺的不是更多规则，而是自动发现规则的回路

Hermes 已经擅长「按项目 skill 执行」，但 Homunculus 暴露了两个差距：第一，Hermes 的行为经验主要靠人写进 skill 或文档；第二，记忆若全量注入，会在 token、相关性和过期知识之间摇摆。
能力Hermes 现状可借鉴方向
自动行为提炼缺失记录工具序列、失败修复路径、用户纠偏，生成候选 skill patch
置信度演化有限为经验规则增加触发次数、最近触发、废弃状态
语义召回粗粒度按项目、目标、近期 git 变化召回 Top-K，而非全量加载
防膨胀硬限制为主引入 TTL、置信度衰减、覆盖式聚合和审计队列
最小可行路径

先别上 Qdrant

对 Hermes 来说，第一步应是工具事件日志 + 会后候选规则，而不是先做重型向量库。行为提炼跑通后，再决定是否需要 Embedding 召回。
优先级：观测确定性 > 候选规则审计 > 置信度演化 > 语义召回。
09 · 结论

适用 / 不适用场景

适用

高频使用 Claude Code、项目结构稳定、个人或小团队风格强、重复修正成本高、能接受本地 Hook 和日志留存的工程环境。

不适用

一次性任务、强监管或不能落本地行为日志的场景、多人共享同一 Agent 但缺少隔离策略的团队、对退出时延极敏感的工作流。
一句话总结：Homunculus 的价值不在让 Claude Code「记得更多」，而在让它用确定性 Hook 学会「你通常怎么把事情做对」，再通过置信度和遗忘机制防止这套本能变成上下文垃圾。
