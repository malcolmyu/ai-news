核心论断

「你为模型写的修补代码注定会过时，因为模型进化永远比你重构快。」

作者从 Anthropic Managed Agents 的 SDK 中发现了隐藏的 Beta 模块，逆向推理出 Anthropic 的四层解耦架构。本质上是把 Agent 从「宠物」（与环境/记忆死死绑定，脆弱）变成「牛马」（无状态、可销毁、可重建）。
"以前大家没解耦，记忆和本地的环境就死死的绑在一起。这等于你把 Agent 当宠物去养。他只要跑错一行配置或者记忆越来越多，系统就会越来越难用，甚至得重装。"
— 费曼学徒冬瓜

架构拆解

Anthropic 四层解耦架构（从 SDK Beta 模块逆向推理）

1Agent + Sandbox 解耦
大脑（模型/规划/决策）与双手（执行沙盒/代码环境）彻底分离。双手崩了直接换一双，不影响大脑状态。
2Coordinator 编排
一个「不干活的指挥官」，唯一的职责是拆任务、派活、验收。花名册里最多管理 20 个专业 Agent，每个有独立的 prompt/tool/MCP。
3Session 管理层
Session ≠ Agent。Agent 是静态模板（定义工具/模型/prompt），Session 是动态实例（对话/线程/记忆）。同一 Agent 可以跑十个独立 Session。
4Session Store（云端记忆）
2026/4/19 被合并的 PR 将记忆从本地搬到 Redis 缓存。上下文不再是 Agent 的一部分，Agent 实现彻底无状态——可 fork、可回滚、可克隆。
心态转变

宠物 vs 牛马

🐕 宠物模式（旧）
Agent = 模型 + 记忆 + 环境 捆绑。跑错配置就崩、记忆膨胀就崩、环境污染就崩。
🐂 牛马模式（新）
大脑只管发指令，底层全是无状态独立沙盒。某个沙盒挂了直接干掉，重新拉个干净的接着干。
"一个配置就能导致全盘崩溃吗？在这种架构下根本就不可能发生。"
本地复刻

Docker 版四层架构实现

作者用一周时间复刻了完整架构：
📦 Worker = Docker 容器，可随时创建/销毁
🧠 创建时决定：模型、harness、skill、SSH key、工作目录
📋 主控服务器通过预定义任务图编排 Worker 交互
⚠️ 已知不足
作者坦承自己的实现不是完全解耦——Agent harness 还塞在 Worker 节点里。结果评估模块也还没做完。
任务图编排

两套实战 Workflow

🔄 Code Review Pipeline
同时并发多个编码 review → 汇总到一个节点 → 统一输出。每个节点独立上下文、独立模型。
🔬 Deep Research Pipeline
多个节点并发搜索 → 多个并发写作节点整理 → 最后汇总做 PPT。每个阶段用不同的模型组合。
"每个节点可以从一个全新的上下文开始，所以每个节点可以是不同的模型。这个就很厉害了。"
模型编排

大小模型组合的威力

每个 Worker 独立指定模型。这意味着：
🔍 搜索/爬取 → 小模型（快、便宜）
🧠 分析/推理 → 大模型（准、深）
✍️ 写作/输出 → 中模型（平衡）
Claude Code / Hermes 很难实现 — 一个 session 内切换多个模型干不同的事。
未来判断

「一部手机指挥云端的蜂群」

作者预见的三个趋势：
1. Tencent Cube Sandbox — 毫秒级沙盒启动替代 Docker，让 Agent 的「销毁重建」成本接近零
2. 云端 Agent 操作系统 — Anthropic 的真正阳谋不是卖 Managed Agents，而是做一个云端的 Agent OS
3. 计算资源计价变革 — 从固定容器服务到动态 Agent 容器的创建/销毁周期
引起反思

我们在争论什么？

作者结尾的发问很有穿透力：
"海外厂商们已经把对 AI 的理解和如何落地上升到了另一个维度。我们还在研究怎么样在本地养多只小龙虾，还在为用 OpenClaw 还是用 Hermes 争论不休。"
提到的已发生事实：Anthropic Managed Agents、Frontier AI Platform、OpenAI Frontier、新兴职业 FDE。都在做同一件事——把 Agent 从个人工具变成企业基础设施。
与你自己的场景

从 Ralph+ 多智能体到「Agent OS」

→
你已经在跑类似架构
Ralph Loop 里「主 Agent 只协调不干活 + 子 Agent 分治」= Anthropic 的 Coordinator + Worker 模式。
→
Session/Memory 还没解耦
Hermes 里 session 和 agent 绑在一起，没有独立 Session Store。这正是这篇视频说的「宠物模式」。
→
Docker 化子 Agent
每个 delegate_task 子 agent 不同的工具集/模型，已经接近 Task Graph 的思想。
→
升级方向
Session ↔ Agent 解耦 + 异步 Coordinator + 云端记忆 = 从「养小龙虾」到「放牛马」。
