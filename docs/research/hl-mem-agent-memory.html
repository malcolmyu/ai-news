HL-Mem：让 Agent 像人一样记忆的本地长期记忆系统

淘天集团直播 AIGC 团队作者「子安」开源的本地化 Agent 长期记忆系统（Apache-2.0）。它把记忆看作一套受治理的认知系统而非数据存储：事实与经验双通道架构，保留不可变原始事件（Event）与可更新的结构化事实（Claim），用 valid time / recorded time 双时钟区分「何时为真」与「何时得知」，把去重、冲突消解、衰减、归档与显式遗忘做成一条默认主链路，底层仅依赖 SQLite 单文件 + 后台 Worker，专为个人 Agent 与中文场景设计。

01 · 核心命题

记忆是受治理的认知系统，不是数据存储

作者用一个病例开场：1953 年，代号 H.M. 的病人为治癫痫切除了海马体，智力、语言、性格全部正常，却再也无法形成新的长期记忆——每天醒来护士都是陌生人。作者给出的判断是：今天的 LLM 就是数字版的 H.M.，单轮对话里聪明惊人，会话一关，一切归零。
HL-Mem 补的不是「存下来」「搜出来」或「形成关系」中的某一环，而是它们之间断开的那条链路：原始事件怎样变成事实、事实怎样被新证据修正、旧记忆怎样退出召回。这套闭环默认只需要一个 SQLite 文件和一个后台 Worker。
"没有长期记忆，再聪明的大脑也只能活在当下。"— HL-Mem 作者 · 子安
02 · 为什么长上下文治不了失忆

装得下 ≠ 用得好，检索之上还要一层治理

一个自然的反驳是「模型有 1M 上下文，把历史全塞进去不就行了」。作者指出这是两个不同的问题：长上下文解决的是「这一次请求能带多少材料」，长期记忆解决的是「跨越很多次交互后，什么值得留下、怎样更新、何时再想起来」。
LongMemEval（ICLR 2025）系统测过：长上下文 LLM 在持续交互记忆任务上有明显精度衰减——lost in the middle、新旧信息互相干扰、跨会话聚合失败。而 RAG 也不够，因为记忆的数据是活的：会重复（同一件事说了八遍）、会矛盾（上个月喜欢的这个月不喜欢了）、会过期（「明天开会」三天后就是垃圾）、会被要求删除。

04 · 设计原点

把「经历」与「认知」分开：双通道事实链

HL-Mem 最核心的设计是一条可追溯的事实链，同时保留一条独立的经验通道。两条通道共享 Event 起点，却按不同规则演化——一条维护认知，一条积累经验。

事实通道（认知）

Event（经历） → Claim（原子事实） → Observation（观察） → Mental Model（心智模型）
        └── Evidence Link 把 Claim 指回原始 Event；模型生成的文字本身不能充当事实来源
Event 是不可变的原始事件（一轮对话、一次工具结果）；Claim 是提取出的最小事实单元（如「用户当前偏好浅色模式」）；Observation / Mental Model 是更高层理解，但始终保留来源关系——底层事实失效时，派生理解会被标记为需要重新计算。这样做看起来比「存一段摘要」麻烦，但换来了三件重要的事：可验证、可更新、可解释。

经验通道（做事）

Event（经历） → Episode（任务级经验） → Trace / Reward（过程与反馈） → Policy（策略） → Procedure / Skill（可复用做法）
Episode 把围绕同一目标的一组 Event 组织成任务级经验；Trace / Reward 分别保存执行轨迹与结果反馈；Policy 表示「在什么情况下优先采用哪种做法」；Procedure / Skill 把稳定有效的做法沉淀成可复用步骤。事实会被新证据纠正，经验会被反馈强化或淘汰——把两者都压成同一种「记忆文本」，系统既解释不了为什么相信一件事，也解释不了为什么选择一种做法。
05 · 整体架构

五层受治理的记忆核心，底层只有 SQLite

事件从接入层进入，沿事实与经验双通道演化，最终由同一个治理核心约束。展开成五层：
层级 职责
接入层 CLI、REST API、MCP 与 Hermes Provider 接口，让不同 Agent 运行时使用同一套记忆
写入层 事实型输入先成为不可变 Event，再经可持久化 Job 进入抽取、准入、去重、冲突和证据提交流程；关键状态按事务提交，失败可重试
认知层 事实通道形成 Claim / Observation / Mental Model；经验通道聚合 Episode、Trace、Policy、Procedure
召回层 先理解问题所指的主体、实体和时间，融合中文 FTS 与向量候选，高置信实体约束隔离同名对象，新近度/重要性/反馈效用参与排序，组装成有 Token 预算的 Context Packet
治理层 来源准入、反馈、TTL、衰减、归档、纠正、遗忘、解释与运行统计；后台 Worker 扮演「睡眠」，hl-mem explain 与 hl-mem ops report 让记忆形成与调用成本都可被看见

为什么没有变成复杂部署

证据链、双时间和生命周期增加的是数据语义，不必同时增加三套外部基础设施。SQLite 负责权威存储，确定性规则先处理可以证明的事实，LLM 只做语言理解，后台 Worker 承担抽取与维护。复杂度没有消失，而是被关进了明确边界：在线召回不等待维护任务，基础数据面不依赖外部向量库或图数据库。底层默认只依赖 SQLite WAL + FTS5 + 向量 BLOB，小规模数据可直接精确扫描向量，数据增大时可选 sqlite-vec。
06 · 一条记忆怎样度过一生

深色模式的完整生命周期 + 双重时间感

回到开头「深色模式」的例子，把管线串起来走一遍：
  1. 「主要用深色模式」先被保存为不可变 Event A，同时记录来源坐标，并提取出 Claim A
  2. 「暂时换成浅色模式」成为 Event B，提取出带时间和「暂时」限定词的 Claim B
  3. 系统判断二者指向同一事实槽位但取值冲突，于是让 B supersede A，同时保留 A 的历史与证据
  4. 问「现在偏好什么」时，当前时间过滤只返回 B；问「之前偏好什么」时，历史查询仍能找到 A
  5. 如果用户显式遗忘 B，对应记忆对象、向量和专属依赖按删除闭环清理，派生理解失效；tombstone 账本继续阻止旧备份把它重新带回

容易被忽略的细节：两种时间戳

valid time——这件事在现实中什么时候为真？recorded time——系统在什么时候知道并记录了它？
例如用户 3 月说「我在杭州工作」，8 月才说「其实 5 月就搬去北京了」——系统既能回答「你 4 月时以为我在哪」（杭州，当时的认知），也能回答「我 4 月实际在哪」（北京，事后修正的事实）。单时间戳的系统只能留一个值，这类问题必然答错。这对迟到数据、纠正、审计和历史回放都很重要——它让记忆不再只是一张当前状态表，而变成一段可以回放的认知历史。
07 · 五个关键设计取舍

如果这条记忆错了、旧了、重复了、太贵了，怎么办？

五个真实的设计取舍，几乎都来自同一个问题：如果这条记忆错了、旧了、重复了，或者太贵了，系统准备怎么办？

取舍一：先保存「案发现场」，再允许系统形成看法

第一条硬规则：Event 不可修改，Claim 只是系统对 Event 的解读。原话作为 Event 留下，抽取器可以升级、Prompt 可以变化、Claim 可以被纠正，但原始 Event 不会跟着改写。这就像保留案卷：即使系统后来理解错了，仍能回答「它当时到底听到了什么」「哪一步把原话解释错了」。
v1.1 又把「案卷从哪里来」纳入准入规则——Event 携带 origin_class 与 session_kind：用户直接表达、外部网页、cron 任务、heartbeat 或 subagent 会话可以被保存，但不再默认拥有同样的事实权威。在 provenance.mode = "enforce" 下，系统会在调用模型之前拦住不适合自动形成 Claim 的来源，把提示词注入、外部噪声和系统自说自话挡在长期认知之外。

取舍二：一句「我改主意了」，背后有两个时钟

很多记忆系统遇到新事实会直接覆盖旧值，但对长期 Agent 来说，「旧值不再有效」和「旧值从未存在」完全是两回事。所以纠正不是一条简单的 UPDATE，而是让新 Claim 通过 supersede 链替代旧 Claim——旧 Claim 退出当前召回，却仍能在历史查询和审计里出现，配合 valid / recorded 双时钟，系统不仅能回答「现在是什么」，还能回答「站在当时，系统知道什么」。

取舍三：相似度 0.99 的两句话，可能差一个事故

「部署 v1.2」和「部署 v1.3」只差一个字符；「允许删除」和「不允许删除」也高度相似。对向量检索它们几乎一样，对执行任务却是完全相反的指令。所以去重没有停在一个 cosine threshold，而是做成一个漏斗：精确哈希先处理完全重复 → 确定性安全门检查主体、数字、版本、日期、路径、极性、引语、姓名和实体等 protected atoms，关键原子必须全部一致才可能合并 → 只有规则无法判断的灰区，才允许进入 LLM 审计。
同样的约束延伸到召回：语义相似回答「像不像」，实体约束回答「是不是在说这个对象」。当查询中出现高置信实体时，默认 entity_constraint_mode = "enforce" 会隔离其他实体的相似记忆。在 v1.1 的冻结门禁中，15 个高置信实体案例全部进入 Top-5，跨实体错误 Top-1 从 15 个降到 0——提升召回质量并不总要换更大的模型，把对象边界设计清楚往往更直接。
作者在这条上选择了一种很保守的偏差：多留一条重复记忆通常只是浪费一点空间，错误合并却可能永久改写事实。

取舍四：把遗忘当成新陈代谢，而不是一个 Delete API

会删除数据不等于会遗忘。真正的遗忘应该回答「什么先忘、什么时候忘、重新用到后会不会更耐久、忘掉后派生结论怎么办」。HL-Mem 把「忘」拆成三层，一层比一层彻底：
  • 自然衰减：根据 scope 与 importance 计算 TTL；激活度按半衰期衰减，访问和正向反馈会延长有效生命。衰减只影响「多容易被想起」，不改写事实置信度
  • 归档（archived）：继续沉寂的记忆退出普通召回、清理向量，但事实和证据仍留在历史中可查证
  • 显式遗忘（Forget）：用户主动要求时，沿依赖关系执行物理删除闭环，清理记忆对象与向量、让派生理解失效；tombstone 账本阻止备份恢复或历史重放让旧记忆复活
这套一键级联的显式遗忘，在裸 RAG 里很难补齐，在被遗忘权与本地隐私场景里却是硬需求。遗忘在这里承担的是记忆质量控制——一个什么都不忘的 Agent，最后会被旧偏好、一次性计划和无关细节填满。

取舍五：让 LLM 少跑几趟，让中文当一等公民

作者从一开始就不想让「记一次东西」触发一串看不见的昂贵调用。同一 Session 的 Event 形成有界窗口（默认最多 5 条、最长等待 120 秒），用一次结构化抽取理解这一小段上下文；超长内容才继续分块；显式写入的结构化记忆甚至可以绕过 LLM 抽取。后面的去重、冲突和维护同样是确定性规则优先——关系发现默认关闭，主链路不会为了构建图谱再请求一次实体/边关系 LLM，因为一条错误关系会沿多跳检索和派生推理继续扩散，形成连锁污染。
v1.1 把这笔账变成可治理的工程能力：Provider 经稳定插件契约接入、必须显式 allowlist；hl-mem ops report 汇总调用量、Token、费用、延迟、失败率，发送前预留预算、完成后按实际结算，无法可靠定价时 fail-closed。「让 LLM 少跑」不再是一句优化原则，而是一条能观测、能预算、能回归的运行约束。
中文这边：中文没有天然分词，通用 FTS 对中文近乎失效。HL-Mem 用 Jieba 领域词典做预分词全文索引，原文不翻译，提取语义中英双语对齐；模型层兼容百炼 / DashScope、智谱和 OpenAI-compatible 接口。作者说得很实在：没有戏剧性的算法突破，更多是分词、Provider、配置和默认值上的工程耐心——也正是这些琐碎工作，决定中文用户能不能把系统真正用起来。
08 · 竞品对比

不同路线，不同工程代价

赛道上有几条成熟路线，不按功能逐项判输赢，而是看它们各自优先解决什么问题、又接受了什么默认工程代价：
路线 代表系统的设计心 默认工程形态 HL-Mem 的选择
轻量记忆与认知分层 Mem0 擅长低门槛 Add / Search；Hindsight 擅长 Retain / Recall / Reflect 与 Mental Model 优先缩短接入路径，由服务或上层应用承接更多治理 把 Event 证据、双时间事实账本，以及 TTL、衰减、归档和遗忘放进同一条主链路
时序知识图谱 Graphiti / Zep 擅长实体关系、事件演化和历史状态查询 通常需要图存储，以及持续的实体/关系抽取、消歧、合并和重算链路 保留时间语义与可选关系发现，但默认关闭自动建图，避免错误边沿多跳推理扩散
Memory OS 与有状态 Agent MemOS 擅长统一多种记忆形态；Letta 擅长把 Memory Blocks、Files 和 Archival Memory 融进 Agent Runtime 记忆与 Agent Runtime 深度协同，一体化体验更强 有意把记忆收窄为独立服务，让 CLI、REST、MCP 和不同 Agent 运行时共享同一份本地记忆
Mem0 先解决低门槛个性化记忆，Graphiti / Zep 先解决关系推理，Letta 先解决有状态 Agent。HL-Mem 选择把四件事绑在同一条主链路：记忆能追溯来源、能回放历史、能按生命周期退出、又不依赖某个 Agent Runtime，中文检索走默认路径。这组组合解释了它的工程取向——Agent 框架还在快速变化，记忆却是最需要长期保存的数据，把记忆独立于 Runtime 可以降低迁移成本；关系推理有价值，但不必每次个人偏好召回都启动图存储与额外抽取。

作者最看重的不是 LongMemEval 的 86% 本身，而是旁边两个对照：全上下文可以直接看到全部历史，Native RAG 可以从原始会话中检索，HL-Mem 则先把历史整理成可更新、可追溯的 Claim 与 Evidence。最终只相差 3 题和 2 题，说明证据、时间与生命周期治理没有换来不可接受的信息损失。结构化记忆把抽取成本放在写入阶段，后续每轮只携带当前问题真正需要的事实和证据——一次整理、多次复用，Agent 使用得越久，反复携带全部历史的成本越高，结构化记忆的复用价值越明显。
10 · 边界与定位

边界决定了 HL-Mem 更擅长什么

更适合

  • 本地个人 Agent、桌面助手，以及中文知识与偏好记忆
  • 需要追问记忆来源、处理事实修正与历史回放，或执行用户遗忘请求的场景
  • 希望记忆独立于 Agent Runtime，先低成本落地、再随规模增强的团队

不应该被误解为

  • 面向不可信多租户的完整 RBAC 或托管平台；namespace 目前只提供逻辑分区
  • 默认开启的大规模图推理系统；关系发现只在需要时显式开启
  • 一次性自动运行所有「类大脑」能力；Observation、Mental Model、Policy 和 Procedure 按真实使用证据逐步开放
这些边界换来的不是功能少，而是故障半径小：高成本、高不确定性的能力必须显式开启；证据、时间、生命周期和数据主权始终留在默认主链路。v1.1 把这条边界固定成一套可运行的基线——来源有准入、记忆可解释、Provider 可替换、模型费用可统计、核心召回有冻结门禁。下一轮功能先看真实 Agent 工作流里哪里反复失败，再决定加什么。
11 · 尾声

记忆给 Agent 的，其实是时间

作者把记忆提到 AGI 基础设施的高度：scaling、test-time compute、长上下文、agentic loop 几条路走到深处会撞上同一堵墙——智能需要时间维度上的连续性。一个每次醒来都失忆的系统，参数再多也只是一个聪明的陌生人，无法从自己的错误里学习，无法积累对你的理解，无法形成「它自己」。
"自我就是记忆的叙事——「我是谁」是用一段段记忆串起来的连续故事。"— 认知科学观点 · 子安 引述
回到那位切掉海马体的 H.M.：手术后他又活了五十多年，却记不住其中任何一天，晚年照镜子仍会被自己的白发吓到——在他自己的故事里，他永远是 1953 年那个 27 岁的年轻人。他失去的远不止记忆，还有继续成为自己的能力。对 Agent 同理：推理能力（LLM）解决的是「此刻多聪明」，工具调用解决的是「能做什么」，而记忆解决的是「它是谁」——偏好的积累、错误的修正、经验的沉淀、承诺的延续，全部长在记忆上。
但连续性也不等于把一切永久保存。没有证据的记忆会制造幻觉，不会更新的记忆会固守旧认知，什么都不忘的记忆最终会淹没在自己积累的噪声里。一个长期存在的 Agent，需要的不只是「记住」，还要能选择、解释、修正和遗忘。
"人类记忆的伟大之处从来不在于存得多，而在于忘得聪明、改得干净、想起来的时候还能说出为什么。模型赋予 Agent 智力，工具赋予 Agent 双手，记忆才让它在时间里成为同一个自己。"— HL-Mem 作者 · 子安
