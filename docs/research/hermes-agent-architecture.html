核心哲学

「不是 coding copilot，是一个会自我进化的自治 Agent」

Hermes Agent 不是一个绑在 IDE 上的编程助手，也不是一个围绕单个 API 的聊天包装器。它是一个自治 Agent，运行时间越长越聪明 — 你的 VPS、GPU 集群、云 VM 都可以作为宿主。你通过 Telegram/Discord/飞书跟它对话，它在你从不会 SSH 登录的机器上自主工作。
The only agent with a built-in learning loop — it creates skills from experience, improves them during use, nudges itself to persist knowledge, and builds a deepening model of who you are across sessions.
— Hermes Agent 官方定义

六大架构亮点

Hermes 最独特的设计选择

🔁 Self-Improving Loop
唯一拥有内置学习循环的 Agent：从对话中自动提取 skill，持续改进，自动持久化知识。Curator 守护进程管理 skill 生命周期 — 追踪使用率、归档过期 skill、防止记忆库污染。
🔧 Tool Gateway 模式
70+ 工具通过 AST 自动发现和注册。plugin 架构实现热插拔，每个工具自带 `check_fn` 可用性检测。Toolset 机制支持按平台/场景按需加载，避免 token 浪费。
🧠 Progressive Disclosure
Skills 遵循渐进式信息披露模式：第一次调用只显示名称+描述，再调用才展开完整内容。最大化节省上下文。100+ skills 可同时存在而不炸 token 预算。
📐 Architecture Patterns
Gateway、Registry、Factory/Plugin、Strategy、Observer/Hook、Chain of Responsibility、Progressive Disclosure、Adapter — 11 种经典架构模式的现代融合实现。
⚡ Prompt Caching
铁律：system prompt 绝不中途改变。以此保证 Anthropic 的 prefix caching 持续命中。Skills 注入通过 slash commands 实现，不破坏缓存断点。
🌐 20+ Messaging Gateway
统一 Gateway 进程调度 Telegram、Discord、飞书、微信等 20+ 平台。两阶段 guard 机制：platform adapter → gateway runner，确保消息安全和 session 隔离。
模块深度解析

核心模块一览

AIAgent Core
12k LOC 核心循环 — provider 选择、prompt 构建、工具执行、重试、回退、callback、压缩、持久化。支持 chat_completions / codex_responses / anthropic_messages 三种 API 模式。
Prompt Builder
从 SOUL.md、MEMORY.md/USER.md、Skills、AGENTS.md 拼接 system prompt。模型级指令特化 + Tool-Use 指南注入。
Context Compressor
默认压缩引擎 — 长对话中段 lossy 摘要。保留 prompt caching 断点。
Messaging Gateway
长驻进程统一调度 20+ 消息平台。授权、session 路由、slash command 分发、cron ticking。
Memory System
有界持久记忆：MEMORY.md(2200chars) + USER.md(1375chars)。session 启动时注入冻结快照。agent 通过 memory 工具自主管理。session_search 使用 FTS5+LLM 摘要。
Skills System
agentskills.io 开放标准。渐进式加载：skills_list→skill_view→skill_view(name,path)。platform-gating、条件激活。agent 自主创建 skill。
Tool Registry
70+工具通过 AST 扫描自动发现。模块级 self-register。按需加载 toolset。文件级依赖链：registry→tools→model_tools→run_agent。
Delegation System
delegate_task 支持最多 3 并发子 agent。独立上下文隔离。Kanban 多 agent 协调。深度限制防递归爆炸。
MCP Bridge
stdio/HTTP MCP Server 连接。工具名自动加 mcp_前缀。per-server过滤。资源/prompt 能力感知。
Cron Scheduler
内置 cron 引擎支持 recurring/one-shot 作业。context_from 链式依赖。Profile 隔离。Script-only (no_agent) 模式零 token 消耗。
Multi-Agent 架构

Delegate → Kanban → Cron：三层调度体系

从单次任务到持续编排，Hermes 构建了完整的多 Agent 调度栈。每一层解决不同的并发/持续时间/隔离需求。
Layer 1: delegate_task — 同步并行
主 Agent 拆解任务，最多3 个 Flash 子 agent并行执行。独立上下文，隔离 workspace。完成后向上汇总。适合 1-3 小时的中等复杂度任务。
Layer 2: Kanban — 异步看板协作
多 Profile 多模型长期协作。Planner (Pro) 拆任务 → Executor (Flash) 认领执行 → Validator 验收。SQLite-backed 看板持久化状态。适合持续数天的项目开发。
Layer 3: Cron Scheduler — 定时自治
系统级 cron 支持 script-only (no_agent) 零 token 模式。context_from 链式依赖。Profile 隔离。适合日报生成、数据监控、定时部署。

Memory Architecture

四层记忆系统

L1: Session Memory
当前对话上下文。超过阈值自动压缩 — 中间轮次 lossy 摘要，保留首尾。通过 FTS5 可跨 session 搜索。
L2: Persistent Memory
MEMORY.md (2200 chars) 存 agent 笔记。 USER.md (1375 chars) 存用户画像。session 启动时冻结注入。两者容量固定，迫使精炼。
L3: Skills Knowledge
108 bundled skills + 自定义 + 可选。渐进式加载，仅展开使用中的 skill。Curator 守护进程管理生命周期。
L4: External Providers
8 种可选 memory backend：Honcho, Mem0, Supermemory, ByteRover, Hindsight, Holographic, OpenViking, RetainDB。

关键设计决策

12 个值得关注的设计选择

Prompt Caching 铁律
system prompt 绝不中途改变。skill slash commands 作为 user message 注入，不破坏缓存断点。
有界记忆 (Bounded Memory)
MEMORY.md 2200 chars / USER.md 1375 chars — 容量上限迫使 agent 做信息精炼，防止记忆库变成垃圾堆。
模块级 Tool 注册
每个 tool 文件在 import 时 self-register，避免中心化配置文件烂掉。AST 自动发现。
Toolset 按需加载
cron 作业可只加载 file+terminal+web，delegation 可只加载 terminal+file — 显著减少 token 开销。
Curator 守护进程
自动追踪 agent 自建 skill 使用率，归档过期 skill。Pinned skill 免于自动过渡。从不删除，只归档。
两阶段 Message Guard
Gateway 的消息安全：base adapter queues → gateway runner 拦截控制命令 → agent call。
Profile 完全隔离
Config + SOUL + AGENTS 完全独立。Kanban worker crash 不影响其他 worker 和主 profile。
Context Compression
中间轮次 lossy 摘要，保留首尾。Preserve prompt caching 断点。支持 replace/wrap/summarize 三种模式。
delegate_task 深度限制
max_spawn_depth=1 防止递归爆炸。子 agent 不可再 delegate。可配置提升。
Skill Progressive Disclosure
首次调用 skills_list() 只看 name+desc，再次 skill_view(name) 才展开内容。100+ skills 共存不炸 token。
OAuth Provider 支持
Qwen OAuth、GitHub OAuth 等 provider 认证流，解决 token 过期自动刷新。
Script-only Cron
no_agent=True 模式 — 纯脚本周期执行，stdout 作为消息发送。零 token 消耗，适合 watchdog 监控。
