Managed Agents：解耦大脑与双手

Anthropic 发布托管 Agent 服务——基于 OS 虚拟化思想，将 Agent 拆解为 Session / Harness / Sandbox 三层接口，让实现可自由演进而接口保持稳定。

01 · Problem

Harness 编码的假设，会随模型进化过期

核心洞察：Agent 的 Harness 编码了关于模型能力的假设——但这些假设随模型进化快速过期。
示例：Claude Sonnet 4.5 过早收尾任务（"上下文焦虑"）→ 给 Harness 加 context resets → 换 Claude Opus 4.5 后行为消失 → resets 变成无用代码。

结论：Harness 必须持续迭代，但硬耦合导致每次更新都大动干戈。
解决方案：把 Agent 拆成三个虚拟化组件——Session（记录）、Harness（循环调用模型）、Sandbox（执行环境）——像 OS 的 process 与 file 抽象一样，接口稳定、实现可演。
02 · Virt. Components

三个虚拟化组件

📋 Session

追加式日志，记录所有事件。持久化在 Harness 外，可任意挂载

🔧 Harness

循环调用 Claude + 路由 tool call。无状态，可随时重建

📦 Sandbox

执行环境，Claude 可写代码、编辑文件。可替换，可横向扩展
03 · Evolution

从 Pet 架构到 Cattle 架构

Monolith 把一切装在一个容器 → 变成"Pet"（命名、独宠、不可丢失）→ Harness / Session / Sandbox 紧耦合 → 失败就是灾难。
04 · Key Interfaces

三个核心 API 接口

每个组件暴露最小 API，让实现自由替换。
05 · Failure Recovery

容器 / Harness 故障恢复流程

Harness 也是 Cattle：Session 日志在外 → Harness 死 → wake(sessionId) → getSession(id) → 从最后一个事件恢复。
06 · Security

安全边界：Token 永不到达 Sandbox

紧耦合时：Claude 生成的代码与凭证同容器 → Prompt injection 只需说服 Claude 读环境变量 → 攻击者可 spawn 新会话。
07 · Performance

TTFT 大幅降低

-60%
p50 TTFT（首次响应时间中位数）
-90%+
p95 TTFT（尾部延迟）
原因：Container 按需 provision()，无需 sandbox 的 session 直接开始推理。
08 · Scaling

Many Brains, Many Hands

每个大脑可以操作多个手，每个手可以被多个大脑传递。接口统一为 execute(name, input) → string。
09 · Design Philosophy

Meta-Harness 设计哲学

核心思想：对接口 Shape 有主见，对背后实现无主见。

📜 接口 = OS 抽象

Session、Harness、Sandbox 像 OS 的 read() / write()。磁盘从 1970s → SSD，接口不变。

🔄 接口兼容多种 Harness

Claude Code 是一种 Harness，任务特定 Harness 也是一种。Managed Agents 都可以容纳。

🧩 Session ≠ 上下文窗口

getEvents() 按位置切片查询，可在 Harness 中做 compaction / trimming 等上下文工程。

🏗️ 容量已知

对 brain 数量、hand 位置/数量不做假设。只保证 Session 持久化 + Sandbox 可执行。
10 · Context Engineering

Session 作为持久化上下文对象

传统方案：compaction / trimming 做不可逆丢弃 → 可能丢关键 token。Managed Agents 将上下文存为 Session Log，可通过 getEvents() 灵活查询。
能力说明
📌 断点续读从上次读到的位置继续，不重播历史
⏪ 回退倒回特定事件前，看上下文
📖 重读在某个 action 之前重新读取上下文
🔧 变换在传递到 Claude 窗口前，可做任意编排（compaction、prompt cache 优化）
关键设计：可恢复的上下文存储（Session）与任意上下文管理（Harness）分离。无法预测未来模型需要什么上下文工程 → 把管理推给 Harness，Session 只保证持久化和可查询。
11 · Key Insights

核心结论

🔑 Harness 必须解耦

模型能力每 6 个月大幅跃升，Harness 编码的假设快速过期。紧耦合导致每次更新重做。

🐄 从 Pet 到 Cattle

所有组件必须可替换、可重建、无状态。失败不是异常——它是架构设计的一等公民。

🛡️ 安全边界在接口

Token 永远不进入 Sandbox。通过 provisioning 时注入或 Vault proxy 隔离。

📉 TTFT 降低 60-90%

按需 provision 容器，不需要 Sandbox 的 session 零等待启动推理。
